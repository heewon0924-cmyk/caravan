# caravan

여러 도시를 오가며 교역하고, 캐러밴과 인물을 성장시켜 자신만의 상단을 만들어가는
**실시간 상인 교역 게임**의 기획 저장소다.

중심은 전투가 아니라 **정보 · 교역 · 이동 · 인물 육성을 조합해 더 좋은 선택을 하는 것**이다.

```text
정보 수집 → 교역품·루트 선택 → 구매 → 캐러밴 편성 → 이동
    → 이벤트 / 시장 변화 / 전투 → 도착 → 판매 → 수익
    → 인물 육성 / 전직 → 더 좋은 루트와 편성 → 더 큰 교역
```

```
서버   Java 21 · Maven                 클라   Phaser 3 (TypeScript) · WebGL
```

**3단계(경제 코어 + 사고팔기 + 캐러밴 이동)까지 만들었다.** 아래 `빌드와 실행` 참조.

## 표시 규칙

문서의 모든 항목에는 셋 중 하나가 붙는다.

| 표시 | 뜻 |
|---|---|
| `[확정]` | 결정됐다. 프로토타입은 이대로 만든다 |
| `[제안]` | 첫 안이다. 숫자까지 적혀 있지만 검증 전이다 |
| `[미결]` | 아직 답이 없다. 지금 정하지 않기로 한 것도 포함 |

`[제안]` 에 숫자가 박혀 있는 건 그 숫자가 맞아서가 아니라
**빈칸보다 틀린 숫자가 고치기 쉽기 때문**이다. 만들고, 재고, 바꾼다.

## 이 게임이 답해야 하는 세 가지

1. **플레이어가 다음 교역을 왜 하고 싶은가?**
   → 지난번에 놓친 가격을 이번엔 맞힐 수 있을 것 같아서. (`00`, `02`)
2. **왜 이 캐릭터를 얻고 싶어 하는가?**
   → 내가 그 길을 골라서 거기까지 데려갔기 때문에. (`06`, `07`)
3. **왜 다른 플레이어보다 더 잘하고 싶어지는가?**
   → 같은 세계를 보고 나만 다르게 읽었다는 걸 보여줄 수 있어서. (`10`)

1차 프로토타입은 **①과 ②만** 검증한다. ③은 멀티가 필요하고,
①②가 재미없으면 멀티로 덮어도 재미없다.

## 1차 프로토타입 한 장 요약

> **목표를 주지 않아도 "한 바퀴 더 돌고 싶다"가 나오는가?**

| | |
|---|---|
| 도시 | 3개 (하른 · 카르덴 · 셀리아) |
| 노선 | 4개 (늑대고개 포함 — 안전길/위험길 한 쌍) |
| 교역품 | 5종 (밀 · 소금 · 옷감 · 철 · 향신료) |
| 인물 | 3칸 편성, 직업 5개, 고유 캐릭터 2명 (리안 · 블래스티) |
| 전투 | 자동, 1열, 결과 5단계 |
| 세계 | NPC 상인 6명, 이벤트 9종, 오프라인 진행 |
| **안 넣는 것** | 멀티, 뽑기, 과금, 거점, 게임 목표 |

자세한 범위와 만드는 순서는 [`docs/20-프로토타입-1차.md`](docs/20-프로토타입-1차.md).

## 빌드와 실행

```bash
mvn test                 # 95개. 각 단계의 합격 기준이 여기 박혀 있다
mvn package              # target/caravan.jar
```

화면은 아직 없다. 1~3단계는 숫자가 맞는지 재는 단계라 콘솔로 본다
([`docs/30-기술-스택.md`](docs/30-기술-스택.md) 5장).

```bash
java -jar target/caravan.jar trade             # 대화형 — 직접 사고팔아 본다
java -jar target/caravan.jar roundtrip 밀 하른 카르덴 --qty 60 --days 2   # 왕복 손익
java -jar target/caravan.jar sim --days 7      # 세계를 7일 굴린다
java -jar target/caravan.jar curve 밀@하른      # 재고에 따른 시세표
java -jar target/caravan.jar data              # 읽어들인 밸런스 데이터
```

`trade` 안에서 쓰는 말: `상태` `시세` `사기 밀 60` `팔기 밀 60` `견적 밀 60`
`길` `출발 카르덴` `출발 늑대고개` `대기 3` `세계` `끝`

```
  하른 에서 밀 60개 매수
    시세      79 G  →  80 G   (+1.2%)
    적분 금액  4,772 G   (시세대로면 4,742 G — 더 냈다 29 G)
    거래세     143 G
    총 지출     4,915 G   (개당 82 G)
```

### 밸런스를 바꾸려면

`src/main/resources/data/` 의 YAML 세 개만 고친다. 코드는 건드리지 않는다.

| 파일 | 내용 |
|---|---|
| `goods.yml` | 품목 · 기준가 · 탄력도 · 부피 |
| `cities.yml` | 도시 · 기준재고 · 생산 · 소비 |
| `routes.yml` | 노선 · 소요 시간 · 위험도 · 통행료 |
| `world.yml` | 시간 배율 · 곳간 상한 · 시세 상하한 · 거래세 · 시작 자본 · 캐러밴 |

숫자를 바꾸면 `WorldDataTest` 가 깨진다. 그게 목적이다 —
문서와 데이터가 조용히 갈라지면 나중에 어느 쪽이 맞는지 알 수 없게 된다.
숫자를 바꿀 때는 테스트와 `docs/02-교역과-가격.md` 를 같이 고친다.
