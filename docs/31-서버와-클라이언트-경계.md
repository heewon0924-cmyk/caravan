# 31 — 서버와 클라이언트의 경계

`30-기술-스택.md` 가 "서버가 JSON 만 내려주고 화면은 클라이언트가 전부 그린다" 로 끝났다.
이 문서는 **그 경계를 어디에 긋고 어떻게 지킬 것인가**를 규칙으로 못 박는다.

"분리한다" 는 말만으로는 안 지켜진다. 편의를 위해 한 번씩 넘나들다 보면
어느새 규칙이 클라이언트에 반쯤 들어가 있고, 그때는 되돌리는 비용이 크다.

---

## 1. 왜 지켜야 하는가

세 가지 이유가 있고, 셋 다 나중에 온다.

**① 클라이언트를 갈아끼울 수 있어야 한다.**
Phaser 는 지금 고른 것이지 영원히 쓸 것이 아니다 (`30` 3장).
폰 위주가 아니게 되거나 연출이 부족해지면 Godot 이나 네이티브로 옮긴다.
그때 **규칙이 클라이언트에 새어나가 있으면 전부 다시 구현해야 한다.**

**② 멀티로 가면 클라이언트를 믿을 수 없다.**
`10` 4장대로 멀티는 나중이지만, 그때 클라이언트가 가격을 계산하고 있으면
누구나 자기 클라이언트를 고쳐서 밀을 1G 에 살 수 있다.
**클라이언트에 있는 규칙은 전부 조작 가능한 규칙이다.**

**③ 밸런스를 서버에서만 고치고 싶다.**
프로토타입의 유일한 기능 요구사항이 밸런스를 바꾸기 쉬운 것이다 (`20` 5장).
숫자가 클라이언트에도 있으면 한 번 고치는 데 두 군데를 고치고 배포를 두 번 해야 한다.

---

## 2. 한 줄 규칙 `[확정]`

> **클라이언트는 규칙을 하나도 모른다. 일어난 일을 받아서 그릴 뿐이다.**

판정은 전부 서버에서 난다. 클라이언트가 하는 일은 셋이다 —
**보여주고, 입력을 받아 서버에 보내고, 서버가 준 결과를 재생한다.**

---

## 3. 지켜야 할 것 `[확정]`

### 판정은 전부 서버

| 판정 | 어디서 |
|---|---|
| 가격 계산 · 적분 가격 · 거래세 | **서버** (`PriceCurve`, `Exchange`) |
| 재고 변화 · 생산 · 소비 | **서버** (`Market`) |
| 전직 확률과 그 결과 | **서버** (7단계) |
| 습격 발생 여부 | **서버** (7단계) |
| 전투 결과 | **서버** (7단계) |
| 이벤트 발생 | **서버** (4단계) |
| 세계 시간 | **서버** (`WorldClock`) |

난수는 전부 서버에서 굴리고 시드를 기록한다 (`07` 4장).
클라이언트가 굴린 난수는 난수가 아니다.

### 예측은 해도 되지만 판정은 안 된다

클라이언트가 **미리 보여주기 위해** 계산하는 것은 허용한다.
슬라이더를 움직일 때마다 서버를 부를 수는 없으니, 가격 곡선 파라미터를 받아
"300개 사면 대략 31,470 G" 를 그 자리에서 그려도 된다.

단 **확정은 언제나 서버 값이다.** 클라이언트가 계산한 값과 서버가 돌려준 값이
다르면 서버가 맞다. 화면에 띄운 숫자와 실제 지불액이 다를 수 있다는 뜻인데,
그건 `Exchange.quoteBuy` 를 눌러 확인하고 사는 흐름으로 푼다.

### 도메인은 자기가 JSON 이 되는 걸 모른다

`com.caravan.world` · `economy` · `trade` 에는 **직렬화 애노테이션을 붙이지 않는다.**
`@JsonProperty` 하나가 붙는 순간 도메인이 전송 형식에 묶이고,
전송 형식을 바꾸려면 도메인을 고쳐야 하는 상태가 된다.

6단계에서 API 를 만들 때 **DTO 를 따로 둔다.**

```
Market (도메인)  →  MarketView (DTO)  →  JSON  →  클라이언트
```

이 변환 지점이 **무엇을 보여줄지 정하는 자리**이기도 하다.
`02` 5장대로 다른 도시 시세는 실시간으로 안 보이고 재고는 4단계로만 보이는데,
그 결정이 구현되는 곳이 바로 여기다. **도메인은 전부 알고, DTO 가 가린다.**

### 클라이언트는 상태를 만들지 않는다

클라이언트가 들고 있어도 되는 것은 **서버가 준 것의 사본과 화면 상태**뿐이다.
스크롤 위치, 열린 탭, 재생 중인 애니메이션 — 이런 건 클라이언트 것이다.

소지금 · 재고 · 화물 · 캐러밴 위치 · 세계 시간은 **전부 서버 것**이다.
클라이언트가 "내가 아는 소지금" 을 따로 계산해서 더하고 빼기 시작하면
서버와 어긋나는 순간이 반드시 온다.

---

## 4. 전투를 어떻게 넘길 것인가 `[제안]`

여기가 경계 설계에서 제일 까다로운 지점이라 따로 적는다.

**서버가 전투를 전부 굴리고, 일어난 일의 목록을 내려준다. 클라이언트는 그걸 재생한다.**

```
서버                                        클라이언트
전투를 끝까지 굴린다
  ↓
[리안이 도적B를 친다, 42피해]
[도적B가 쓰러진다]              →  JSON  →   애니메이션으로 재생
[블래스티가 관통을 쓴다]                      (또는 건너뛰고 결과만)
[승리 · 화물 손실 없음]
```

이 구조가 여러 문제를 한꺼번에 푼다.

* **전투 규칙이 클라이언트에 없다.** 갈아끼울 때 연출만 다시 만든다
* **건너뛰기가 공짜다.** `08` 2장이 "언제나 건너뛸 수 있다" 고 했는데,
  로그의 마지막 줄만 읽으면 된다. 결과가 달라질 수 없다
* **연출을 통째로 바꿔도 결과가 안 바뀐다.** 밸런스와 연출이 완전히 분리된다
* **멀티에서 조작이 불가능하다**
* 나중에 **리플레이를 공유**할 수 있다 — "내 해적왕이 이렇게 싸웠다"

`08` 이 자동전투로 정한 것과 정확히 맞물린다. 플레이어가 전투 중에 아무것도 하지
않으므로 **서버가 미리 다 굴려놔도 아무 문제가 없다.**

> 만약 나중에 전투에 수동 조작을 넣고 싶어지면 이 구조가 무너진다.
> 그때는 경계를 다시 설계해야 한다 — 그게 `08` 2장이 자동전투를 고수하는
> 또 하나의 이유다.

## 5. 레이어

```
┌─────────────────────────────────────────┐
│  클라이언트 (Phaser · TypeScript)        │   그린다 · 입력 받는다 · 재생한다
└────────────────┬────────────────────────┘
                 │  JSON (HTTP)
┌────────────────┴────────────────────────┐
│  web   — 컨트롤러 · DTO · 인증           │   6단계
├─────────────────────────────────────────┤
│  app   — 유스케이스 조립                 │   6단계
├─────────────────────────────────────────┤
│  도메인 — world · economy · trade        │   1~5단계. 프레임워크 의존 없음
├─────────────────────────────────────────┤
│  data  — YAML 밸런스 데이터              │
└─────────────────────────────────────────┘
```

**화살표는 위에서 아래로만 간다.** 도메인은 위 레이어를 모른다.
도메인이 `web` 의 무언가를 import 하는 순간 경계가 깨진 것이다.

## 6. 지금 상태

| | |
|---|---|
| 도메인에 프레임워크 의존 | **없음** — Jackson 은 `data` 패키지 안에서만 쓴다 |
| 도메인에 직렬화 애노테이션 | **없음** |
| 판정이 도메인 밖에 있는 것 | **없음** |
| DTO 레이어 | 아직 없음 (6단계) |

### 콘솔은 예외가 아니다

`com.caravan.cli` 는 도메인 객체를 직접 만진다. 경계를 어긴 것처럼 보이지만
**콘솔은 서버 안에서 도는 개발 도구**라서 괜찮다 — 네트워크 건너편에 있지 않다.

다만 **콘솔은 좋은 시험지이기도 하다.** 6단계에서 API 를 만들 때
콘솔도 같은 DTO 를 거쳐 가게 바꾸면, Phaser 를 만들기 전에 경계가 실제로 쓸 만한지
확인할 수 있다. 화면에 필요한 게 DTO 에 없으면 그때 드러난다.

`[미결]` 그렇게 할지는 6단계에서 정한다. 프로토타입에 과할 수도 있다.

---

## 7. 갈아끼울 때 실제로 다시 쓰는 것

경계를 지켰을 때 클라이언트를 Phaser → 다른 것으로 바꾸면 무엇을 다시 쓰게 되는가.

| | 다시 쓰나 |
|---|---|
| 가격 · 전직 · 전투 규칙 | **아니오** |
| 밸런스 숫자 | **아니오** |
| API 와 DTO | **아니오** |
| 에셋 (그림 · 소리) | 아니오 (포맷만 맞으면) |
| 화면 배치와 연출 | **예** |
| 입력 처리 | **예** |

**다시 쓰는 것이 "화면" 뿐이어야 한다.** 이 표에서 "예" 가 하나라도 늘어나면
경계가 새고 있다는 뜻이다.
