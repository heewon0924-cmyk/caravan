# 02 — 교역과 가격

원문 4장에 답하는 문서다. **이 저장소에서 가장 중요한 문서다.**

`00` 에 적은 대로 이 게임의 합격 기준은 "예측이 맞는 경험"이고,
그건 전부 여기 있는 수식 하나에 달려 있다.

---

## 1. 대원칙 `[확정]`

> **가격은 난수로 흔들리지 않는다. 재고로 움직인다.**

가격에 난수를 직접 섞으면 플레이어는 예측을 포기한다. 포기하면 `00` 의 ①이 무너진다.

그래서 이렇게 한다.

```
이벤트 · NPC · 플레이어 거래  →  재고가 변한다  →  가격이 따라 변한다
```

난수는 **이벤트가 일어나는지 여부**에만 들어간다. 이벤트가 일어난 뒤의 가격은 완전히 결정론적이다.
흉년이 났다는 걸 아는 플레이어는 밀값이 얼마까지 오를지 **계산할 수 있어야 한다.**

이게 "가격을 보는 게임이 아니라 가격의 이유를 보는 게임"(원문 24장 ①)의 실제 구현이다.

---

## 2. 가격 수식 `[제안]`

도시 `c`, 품목 `g` 의 현재 시세:

```
P = P_base(g) × ( S_ref(c,g) / S(c,g) ) ^ e(g)
```

| 기호 | 뜻 |
|---|---|
| `P_base(g)` | 품목의 세계 기준가. 도시와 무관한 고정값 |
| `S_ref(c,g)` | 그 도시가 그 품목을 "적당히" 가지고 있는 양 |
| `S(c,g)` | 현재 재고 |
| `e(g)` | 탄력도. 클수록 재고에 민감하게 반응한다 |

재고가 기준재고와 같으면 정확히 기준가다. 재고가 줄면 오르고, 늘면 내린다.

**최종 가격은 `P_base × [0.35, 3.0]` 으로 자른다.**
재고가 0에 수렴할 때 가격이 무한대로 가는 걸 막고, 위쪽 한계를 알 수 있게 한다.

### 계산 예 (밀, `P_base=100`, `S_ref=2000`, `e=0.6`)

| 재고 | 계산 | 시세 |
|---:|---|---:|
| 3000 | (2000/3000)^0.6 = 0.784 | **78 G** |
| 2000 | 1.000 | **100 G** |
| 1200 | (2000/1200)^0.6 = 1.358 | **136 G** |
| 800 | (2000/800)^0.6 = 1.733 | **173 G** |
| 400 | (2000/400)^0.6 = 2.627 | **263 G** |
| 100 | 상한에 걸림 | **300 G** |

플레이어가 창고 재고를 볼 수 있다면 이 표는 **머리로 계산 가능하다.**
그게 목적이다. 재고 공개 범위는 5장에서 다룬다.

## 3. 대량 거래는 가격을 민다 `[확정]`

300을 사면 300개를 전부 마지막 가격에 사는 게 아니다. **사는 동안 가격이 오른다.**
수식을 재고에 대해 적분한 값이 실제 지불액이다.

```
C(q) = P_base · S_ref^e / (1−e) · [ S₀^(1−e) − (S₀−q)^(1−e) ]
```

밀 예시로 재고 2000에서 300을 사면:

* 시작 시세 100 G, 다 사고 난 뒤 시세 110 G
* 실제 지불액 31,322 G → **평균 단가 104 G**

이 한 줄이 여러 문제를 동시에 푼다.

* **무한 차익이 막힌다.** 싼 도시에서 전부 쓸어담을수록 평균 단가가 올라간다
* **캐러밴 용량이 진짜 제약이 된다.** 많이 싣는 게 항상 이득이 아니다 (`05`)
* **매도도 같다.** 한 도시에 한꺼번에 쏟으면 내가 내 가격을 무너뜨린다
* 별도의 "슬리피지 시스템"이나 "1회 거래 제한"이 필요 없다. 수식이 알아서 한다

> 구현 주의: `e` 는 1이 아니어야 한다. `e=1` 이면 적분이 로그가 되어 위 식이 깨진다.

## 4. 세계가 재고를 움직인다 `[제안]`

### 틱

**세계는 실시간 10분마다 한 번 갱신한다.** 현실 하루 = 144틱.
각 틱마다 도시별로 생산량을 더하고 소비량을 뺀다.

10분인 이유: 더 짧으면 서버가 아깝고, 더 길면 "잠깐 나갔다 온 사이에 시세가 변했다"는 감각이 사라진다.
1시간짜리 이동 중에 6번 갱신되므로, **도착했을 때 출발 시점과 값이 다르다.** 그게 긴장이다.

### 프로토타입 생산·소비표 (현실 하루 기준)

| 도시 | 품목 | 생산/일 | 소비/일 | 기준재고 `S_ref` |
|---|---|---:|---:|---:|
| 하른 | 밀 | 720 | 240 | 2,000 |
| | 철 | 0 | 60 | 200 |
| | 소금 | 0 | 80 | 250 |
| | 옷감 | 0 | 30 | 120 |
| | 향신료 | 0 | 6 | 30 |
| 카르덴 | 밀 | 0 | 300 | 600 |
| | 철 | 260 | 40 | 900 |
| | 소금 | 0 | 90 | 200 |
| | 옷감 | 0 | 40 | 120 |
| | 향신료 | 0 | 8 | 30 |
| 셀리아 | 밀 | 0 | 260 | 700 |
| | 철 | 0 | 70 | 250 |
| | 소금 | 180 | 60 | 600 |
| | 옷감 | 150 | 50 | 500 |
| | 향신료 | 90 | 10 | 300 |

세 도시 모두 **혼자서는 굶는다.** 하른은 밀만 남고 철이 없고, 카르덴은 철만 남고 밀이 없다.
누군가 실어 나르지 않으면 셋 다 망한다. 그게 플레이어가 있어야 할 이유다.

### 기준가와 탄력도

| 품목 | `P_base` | `e` | 성격 |
|---|---:|---:|---|
| 밀 | 100 | 0.6 | 무겁고 싸다. 부피 대비 이익이 작다 |
| 소금 | 140 | 0.6 | 보존식. 어디서나 쓴다 |
| 옷감 | 320 | 0.7 | 가볍고 비싸다 |
| 철 | 400 | 0.7 | 무겁고 비싸다. 군사 이벤트에 민감 |
| 향신료 | 900 | **1.2** | 가볍고 매우 비싸다. **흔들림이 가장 크다** |

향신료의 `e` 가 두 배인 게 중요하다. 재고가 조금만 변해도 값이 크게 튄다 —
**향신료는 정보가 돈이 되는 품목**이고, 밀은 꾸준한 품목이다.
같은 가격 수식으로 성격이 다른 상품을 만드는 방법이 탄력도 하나다.

### 잉여는 쌓이지 않는다 `[제안]`

하른의 밀은 하루 480씩 순증한다. 놔두면 재고가 폭주해 가격이 바닥에 붙는다. 둘로 막는다.

1. **곳간 상한** — 재고가 `S_ref × 3` 을 넘으면 초과분은 매 틱 5%씩 사라진다 (상해서 버린다)
2. **NPC 상인** — 잉여를 사서 부족한 도시로 나른다 (`09`)

NPC가 없으면 세계가 정지한다. **NPC 상인은 장식이 아니라 경제의 필수 부품이다.**

## 5. 플레이어가 볼 수 있는 것 `[제안]`

| 정보 | 현재 도시 | 다른 도시 |
|---|---|---|
| 시세 | 실시간 | **마지막으로 본 시점의 값 + 경과 시간** |
| 재고 | 대략값 (많음/보통/적음/희귀) | 안 보임 |
| 생산·소비 성향 | 보임 (한 번 방문하면 영구) | 방문했으면 보임 |
| 진행 중인 이벤트 | 보임 | 소문으로만 (`04`) |

핵심은 **다른 도시의 시세가 실시간으로 보이면 안 된다**는 것이다.
전부 보이면 이 게임은 최적 루트를 푸는 계산기가 되고, 정보(`04`)와 이동(`03`)이 동시에 죽는다.

대신 **마지막으로 본 값과 "3시간 전 정보"라는 꼬리표**를 같이 준다.
플레이어는 3시간 동안 얼마나 변했을지를 생산·소비 성향으로 **추정**해야 한다.
그 추정이 이 게임의 실제 플레이다.

재고를 정확한 숫자가 아니라 4단계로만 주는 것도 같은 이유다.
숫자를 주면 계산기가 되고, 단계를 주면 감이 된다.
단, 생산·소비 성향은 정확히 공개한다 — **추정의 재료까지 감추면 그냥 도박이다.**

## 6. 거래 비용 `[제안]`

* **거래세 3%** — 사고팔 때 각각. 왕복하면 6%가 날아간다
* 상인 계열 인물이 캐러밴에 있으면 최대 1.5%까지 낮아진다 (`06`)
* 이동 비용은 별도 (`05`)

거래세가 있어야 **"움직일 가치가 있는 차익"의 하한선**이 생긴다.
6% 안쪽 차익을 보고 왕복하면 손해다. 이게 플레이어에게 "이건 갈 만한가?"를 묻게 한다.

## 7. 경제 리셋 `[미결]`

원문 26장의 질문. 지금 답을 미룬다.

* 싱글 프로토타입에는 **리셋 없음** `[확정]` — 검증할 거리가 아니다
* 멀티로 가면 필요해질 수 있다. 시즌제와 묶인 질문이라 `10` 에서 같이 다룬다

## 8. 검증해야 할 것

프로토타입에서 **반드시 재봐야 하는 것**들이다. 숫자가 아니라 감각을 잰다.

1. 플레이어가 재고 4단계만 보고 시세를 **±20% 안으로 추정**할 수 있는가
2. 흉년 소문을 듣고 밀을 산 플레이어가 실제로 **이득을 보는가**
3. 세 도시 왕복 한 바퀴의 수익률이 **자본의 5~15%** 안에 들어오는가
   — 너무 낮으면 지루하고, 너무 높으면 며칠 만에 끝난다
4. 향신료 한 방과 밀 왕복 세 번이 **비슷한 기대값**인가
   — 비슷해야 "위험을 고를" 이유가 생긴다
5. 계산을 전혀 안 하고 아무거나 싣고 다녀도 **망하지는 않는가**
   — 망하면 진입장벽이 되고, 잘 벌면 계산할 이유가 사라진다
