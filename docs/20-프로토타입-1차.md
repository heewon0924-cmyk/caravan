# 20 — 1차 프로토타입

**지금 실제로 만들 것은 이 문서에 적힌 것뿐이다.**
다른 문서에 `[확정]` 으로 적혀 있어도, 여기 없으면 아직 안 만든다.

원문 27장에 대응한다.

---

## 1. 이 프로토타입이 답해야 하는 질문

딱 하나다.

> **목표를 주지 않아도 "한 바퀴 더 돌고 싶다"가 나오는가?**

나오면 이 게임은 된다. 안 나오면 도시를 30개로 늘려도, 캐릭터를 100명 만들어도 안 된다.

부차적으로 세 가지를 같이 잰다.

1. 플레이어가 **시세를 예측하려고 시도하는가** (`02` 8장)
2. 전직 결과를 보고 **"아깝다"** 인가 **"짜증난다"** 인가 (`07` 7장)
3. 각성한 캐릭터를 보고 **"이거 내가 만들었다"** 가 되는가 (`06` 2장)

## 2. 만드는 것

### 세계

* 도시 **3개** — 하른 / 카르덴 / 셀리아 (`01` 4장)
* 노선 **4개** — 산기슭길 / 광산가도 / 해안가도 / **늑대고개** (`03` 4장)
* 교역품 **5개** — 밀 / 소금 / 옷감 / 철 / 향신료 (`02` 4장)
* 세계 시간, 10분 틱, **6배속** (`03` 3장)
* 오프라인 진행 (lazy catch-up)

> **늑대고개는 반드시 넣는다.** 안전길/위험길 한 쌍이 `00` 의 두 번째 결정 전부다.
> 이게 없으면 이동이 대기 시간으로만 남는다.

### 교역

* 재고 기반 가격 수식 + 상하한 클램프 (`02` 2장)
* **적분 가격** (`02` 3장) — 대량 거래가 시세를 민다
* 생산·소비 틱, 곳간 상한
* 거래세 3%
* **다른 도시 시세는 마지막으로 본 값 + 경과 시간만** (`02` 5장)
* 재고는 4단계로만 표시

### 정보

* 소문 — 정확도 / 신뢰도 / 출처 / 유효기간 (`04` 2장)
* 도시 도착 시 자동 획득 + 주점에서 듣기
* **낡은 소문**이 실제로 존재할 것 (`04` 3장)

### 인물과 전직

* 능력치 4개 — 무력 / 통찰 / 상재 / 인내 (`06` 3장)
* 직업 **5개** — 검사 / 해적 / 창잡이 / 해적왕 / 창의신
* 고유 캐릭터 **2명** — 리안 / 블래스티
* 가중치 기반 랜덤 전직 + 도시·능력치·교관 보정 (`07` 2장)
* **최종 확률은 표시하지 않는다** (`07` 3장)
* 천장, 되돌리기 (`07` 4·6장)
* 인물 수급은 **도시 고용**만 (`06` 6장). 뽑기 없음

### 캐러밴과 전투

* 캐러밴 **1대**, 인물 **3칸**, 용량 60 고정
* 적재율에 따른 속도 저하 (`03` 5장)
* 화물 가치에 따른 습격 확률 (`05` 5장)
* 자동전투 1열, 캐릭터당 특성 1 + 스킬 1
* 결과 **5단계** (`08` 5장). 인물은 죽지 않는다
* 전투 연출 최소 (로그로 충분)

### 세계 운영

* NPC 상인 **6명** (`09` 2장)
* 이벤트 **9종** (`09` 3장), 예고 포함

## 3. 만들지 않는 것

여기 적힌 건 **까먹은 게 아니라 빼기로 정한 것**이다.

| 빼는 것 | 언제 | 왜 |
|---|---|---|
| 멀티플레이 | 루프 확인 후 | 재미의 출처가 섞인다 (`10` 4장) |
| 6칸 편성 | 3칸이 재미있으면 | 3칸으로도 기회비용은 생긴다 |
| 캐러밴 여러 대 | 한참 뒤 | 게임의 성격이 바뀐다 (`10` 1장) |
| 거점·창고·시설 | 한참 뒤 | 같은 이유 |
| 생산·가공 | 한참 뒤 | 교역 자체를 바꾼다 (`05` 3장) |
| 전열/후열 | 6칸과 함께 | 3인 1열로 충분 |
| 계절, 전쟁, 국가 | 미정 | 이벤트로 대체 가능한지 먼저 본다 |
| 게임 목표·엔딩 | **의도적으로** | 목표 없이 재미있는지가 측정값 (`10` 3장) |
| 과금 | 안 함 | (`10` 5장) |
| 뽑기 | 안 함 | (`06` 6장) |

## 4. 만드는 순서 `[제안]`

각 단계마다 **직접 해보고** 다음으로 간다. 순서가 곧 위험 순서다 —
제일 위험한 걸 제일 먼저 만든다.

| 단계 | 만드는 것 | 끝났다고 볼 기준 |
|---|---|---|
| **1** | 세계 시간 · 틱 · 도시 3개 · 재고 · 가격 수식 | 아무도 안 건드려도 7일간 경제가 발산하지 않는다 (`09` 4장) |
| **2** | 사고팔기 + 적분 가격 + 거래세 | 콘솔로 사고팔면서 시세가 밀리는 게 보인다 |
| **3** | 캐러밴 이동 · 노선 4개 · 오프라인 진행 | **여기서 한 바퀴를 돌아본다.** 재미없으면 멈추고 1~3을 다시 본다 |
| **4** | NPC 상인 · 이벤트 9종 | 방치해도 시세가 의미 있게 움직인다 |
| **5** | 소문 | 소문 듣고 움직인 쪽이 실제로 더 번다 |
| **6** | 인물 · 전직 · 천장 · 되돌리기 | 해적왕까지 밀어붙여본다 |
| **7** | 습격 · 자동전투 · 결과 5단계 | 늑대고개를 갈지 말지 진짜로 고민된다 |
| **8** | 각성 · 리안 · 블래스티 | **"이거 내가 만들었다"가 나오는가** |

**3단계가 첫 관문이고 8단계가 최종 관문이다.**
3단계에서 재미없으면 4~8을 만들어도 소용없다. 거기서 멈추고 `02`·`03` 을 다시 설계한다.

화면은 **8단계까지 최소한으로 둔다.** 텍스트와 표로 충분하다.
그림에 시간을 쓰기 시작하면 밸런스를 바꾸기 싫어지고, 프로토타입은 밸런스를 바꾸려고 만드는 것이다.

## 5. 구조상의 제약 `[확정]`

싱글로 만들지만 **나중에 여러 명이 들어와도 안 뒤집히게** 짠다.
비용이 거의 안 드는데 안 지키면 나중에 전부 다시 써야 하는 것들이다.

1. **시장 상태는 플레이어가 아니라 세계가 소유한다.** 재고·가격은 도시에 붙는다
2. **거래는 함수로 분리한다.** `구매(주체, 도시, 품목, 수량)` — 주체가 플레이어든 NPC든 같은 함수를 쓴다
3. **세계 시간은 절대 시각으로 저장한다.** 플레이어의 접속 시각에 의존하지 않는다
4. **난수는 서버에서 굴리고 시드를 기록한다** (`07` 4장)
5. **도시·품목·노선·직업·이벤트는 데이터로 둔다.** 코드에 하드코딩하지 않는다
   — 프로토타입에서 가장 자주 바꿀 것이 숫자다. 숫자를 바꾸는 데 빌드가 필요하면 안 바꾸게 된다

5번이 특히 중요하다. **밸런스를 바꾸기 쉬운 것이 프로토타입의 유일한 기능 요구사항이다.**

## 6. 기술 스택 `[확정]`

정했다. **`30-기술-스택.md` 참조.**

```
서버   Java 21 (17 타깃) · Maven · 1~3단계는 프레임워크 없이 순수 도메인 + 콘솔
클라   Phaser 3 (TypeScript) — WebGL 캔버스. 6~7단계에 시작한다
배포   링크 하나. 지인들이 폰으로 연다
```

핵심은 **서버가 JSON 만 내려주고 화면은 클라이언트가 전부 그린다**는 것이다.
서버가 HTML 을 그려 내려주는 방식이 아니다.

1~3단계에는 화면도 HTTP 도 DB 도 없다. 그래서 여기서 정한 스택은
**사실상 1~3단계를 어떻게 검증할 것인가**에 대한 답이다 — 콘솔과 테스트로 한다.
