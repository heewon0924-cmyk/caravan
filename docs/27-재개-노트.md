# 27 — 재개 노트

**몇 달 뒤에 이 저장소를 다시 열었을 때 제일 먼저 읽을 문서.**

코드를 복원하는 건 쉽다. 비싼 건 *"내가 무슨 생각으로 이렇게 했더라"* 를
되찾는 시간이다. 그걸 줄이려고 쓴다.

마지막 작업: **6단계 완료**. 테스트 148개 통과.

---

## 1. 한 문단으로

3도시 교역 게임의 **서버 코어**가 6단계까지 서 있다. 가격은 재고에서 나오고,
NPC 상인 14명이 물건을 나르고, 사건이 돌고, 소문이 퍼지고, 사람을 고용해 전직시킬 수 있다.
**화면은 아직 없다** — 콘솔로만 논다. 전투는 안 만들었고, 일부러 안 만들었다.

## 3. 다음 한 걸음

**7단계(습격·전투)를 바로 시작하지 않는다.** 먼저 정할 것이 있다.

### 결정 ①: 전투에 볼륨을 주되 자동전투를 유지할 것인가 `[가장 급함]`

`11` 3장에 자세히 적었다. 요점만:

* **"볼륨 있는 전투" 가 "수동 조작" 을 뜻하지 않는다.** 편성 · 스킬 · 지형 · 진형으로
  깊이를 주면 자동전투와 리플레이 구조(`31` 4장)가 그대로 산다
* **실시간 조작 하나만 구조를 깬다.** 넣으면 클라이언트가 전투 규칙을 알아야 하고,
  경계가 새고, 멀티에서 조작이 가능해지고, 클라이언트를 갈아끼울 때 전투를 다시 만든다

**권하는 답: 자동 유지 + 편성 깊이.** 이걸 정하고 나서 7단계를 시작한다.

### 결정 ②: 사람이 직접 해보고 재미있는가 `[이것도 급함]`

기계는 다 돌지만 **자동으로 잴 수 없는 것들**이 남아 있다.

* 전직 결과를 보고 **"아깝다" 인가 "짜증난다" 인가** — 이 한 줄이 전부다 (`26` 7장)
* 대기 중에 시세가 변해서 **아까워지는** 경험이 실제로 생기는가 (`23` 3장 (라))
* 6배속(2시간 노선 = 현실 20분)이 **긴장인가 지루함인가** (`03` 3장)

**`trade` 로 한 시간만 놀아보면 답이 나온다.** 이게 7단계보다 먼저다.

## 4. 열려 있는 결정 (급한 순)

| | 어디 | 왜 급한가 |
|---|---|---|
| 전투 볼륨 · 자동전투 유지 | `11` 3장 | 7단계를 막고 있다 |
| 인물을 어떻게 얻는가 (뽑기?) | `06` 6장, `11` 6장 | 수집 비중이 커지면 압력이 는다. **바꾸면 제일 비싸다** |
| 고유 캐릭터 외형 예산 | `90` 4장 | 캐릭터 수를 정하고, 그게 직업 트리 규모를 정한다 |
| 탐험으로 무엇을 얻는가 | `11` 4장 | 보물로 돈을 벌면 `00` ①이 무너진다 |
| 해상이 부차적이면 리안의 자리 | `11` 5장 | 육상 중심이면 리안이 노는 시간이 길다 |
| 지역(region) 계층 | `11` 7장 | 세계가 넓어져야 정보가 값을 한다 (`25` 4장) |

## 5. 하지 말 것

* **7~8단계를 결정 ① 없이 만들지 말 것.** 다시 만들게 된다
* **1~6단계를 다시 설계하지 말 것.** 방향이 커져도 전부 그대로 쓴다 (`11` 2장)
* **뽑기를 가볍게 넣지 말 것.** `00` ②의 답이 통째로 바뀐다
* **밸런스 숫자를 코드에 넣지 말 것.** `ArchitectureTest` 가 막지만, 막히면 데이터로 옮긴다
* **클라이언트에 규칙을 넣지 말 것.** `31` 과 `ArchitectureTest`

## 6. 만들면서 배운 것 — 반복하지 말 것

단계마다 한 번씩 물린 것들이다. 같은 부류가 또 올 것이다.

| 배운 것 | 어디서 |
|---|---|
| 세계 전체 생산 < 소비면 **누가 날라도 어느 도시는 굶는다.** 도시별로 보면 안 보인다 | `24` 2장 |
| **NPC 최소 마진이 곧 플레이어 수익률**이다. 인원은 처리량만 정한다 | `24` 5장 |
| 남는 것이 **산지에 고이면** 산지 값이 계속 내려가 수익률이 벌어진다 | `24` 4장 |
| 최댓값을 고르는 판단에 **잡음을 섞으면 손해**다 (승자의 저주) | `25` 3장 (가) |
| **정보에는 "언제" 가 있어야** 쓸모가 있다. 예고가 왕복보다 길면 못 쓴다 | `25` 3장 (나) |
| 신뢰도가 **너무 높아도 손해**다 — 과장된 정확도를 증폭하기 때문 | `25` 3장 (다) |
| 세계끼리 편차가 커서 **시드 10개로는 아무 말도 못 한다** | `25` 3장 (마) |
| 게터가 있는데 **필드를 직접 읽으면** 조용히 어긋난다 | `26` 6장 |
| 큰 수를 "넉넉히" 주면 **부동소수점에 손익이 묻힌다** | `22` 4장 |
| 만들고 **직접 굴려보지 않으면** 콘솔이 죽은 세계에서 도는 걸 모른다 | `25` 2장 |

그리고 가장 중요한 것 하나.

> **숫자가 초록색이 될 때까지 맞추지 않는다.** 5단계에서 소문이 값을 못 했을 때
> 튜닝을 멈추고 왜 안 되는지를 적었다. 그게 맞았다 — 계속 맞췄으면 멍청한
> 자동 상인에게 세계를 과적합시켰을 것이다 (`25` 1장).

## 7. 구조 한 장

```
src/main/java/com/caravan/
  economy/   PriceCurve            가격 곡선과 적분 가격
  world/     World City Market     도시와 시장, 세계 시계
  trade/     Exchange Trader Cargo 모든 매매가 지나는 곳
  travel/    Caravan Travel        캐러밴과 노선
  npc/       NpcMerchant NpcFleet  NPC 상인 14명
  event/     EventEngine           세계 사건
  rumor/     RumorMill RumorBoard  소문
  people/    Person Job Crew       인물과 전직
  app/       Simulation Company    조립 — 유스케이스 계층
  cli/       TradeConsole 등       콘솔 (규칙이 하나도 없다)
  data/      *Spec WorldData       YAML 을 읽고 검증한다

src/main/resources/data/           ← 밸런스는 전부 여기
  goods.yml cities.yml routes.yml events.yml jobs.yml world.yml
```

**화살표는 위에서 아래로만 간다.** `ArchitectureTest` 가 매 빌드마다 검사한다.

## 8. 스택과 클라이언트

| | |
|---|---|
| 서버 | Java 21 · Maven · **프레임워크 없음** (6단계까지 필요 없었다) |
| 클라이언트 | **아직 없다.** Phaser 3 (TypeScript) 로 정했지만 안 시작했다 |
| DB | 없다. 세계는 시드와 데이터 파일에서 다시 만들어낼 수 있다 |

Spring Boot 와 MariaDB 는 **화면이 필요해질 때** 붙인다. 도메인 코드에
프레임워크 의존이 하나도 없어서 `pom.xml` 과 앱 클래스만 늘어난다 (`30` 2장).

`[미결]` Phaser 를 프로토타입용으로만 볼지 그대로 갈지는 안 정했다 (`30` 3장).
